

\# ADR-006: Estrategia de extracción Strangler Fig



\## Estado

Aceptado.



\## Contexto



BookStack funciona actualmente como una aplicación monolítica que concentra funcionalidades de contenido, búsqueda, actividad, exportación, archivos multimedia y administración de usuarios y permisos.



La extracción directa de estas funcionalidades puede generar dependencias, interrupciones del servicio y problemas de consistencia de datos.



Se necesita una estrategia que permita incorporar microservicios progresivamente, manteniendo el funcionamiento del sistema existente.



\## Decisión



Se adopta el patrón arquitectónico Strangler Fig para realizar una extracción incremental de funcionalidades desde BookStack hacia microservicios independientes.



La integración se realizará exclusivamente mediante:



\- API REST.

\- Webhooks.

\- API Gateway como punto de entrada a las funcionalidades extraídas.



No se modificará el código fuente de BookStack.



Las funcionalidades se extraerán progresivamente, comenzando por Search, Audit, Export y Media.



\## Alternativas consideradas y rechazadas



\### Reescritura completa del monolito



Se rechaza porque implica un esfuerzo elevado, mayor riesgo de interrupciones y una migración simultánea de todas las funcionalidades.



\### Extracción directa mediante acceso compartido a MariaDB



Se rechaza porque genera acoplamiento entre los servicios y dificulta mantener la independencia de los datos.



\### Modificación del código fuente de BookStack



Se rechaza porque la estrategia definida exige mantener BookStack sin modificaciones en su código fuente y utilizar exclusivamente interfaces de integración.



\## Consecuencias



\### Positivas



\- Permite una migración gradual.

\- Reduce el riesgo de reemplazar el sistema completo.

\- Facilita la incorporación y validación de microservicios.

\- Mantiene BookStack operativo durante la transición.

\- Permite revertir funcionalidades extraídas si ocurre un problema.



\### Negativas



\- Durante la transición coexistirán el monolito y los microservicios.

\- Será necesario administrar integraciones REST y Webhooks.

\- Pueden aparecer problemas de consistencia eventual.

\- Aumentará temporalmente la complejidad operativa y de monitoreo.



\## Referencias



\- Patrón Strangler Fig.

\- API REST.

\- Webhooks.

\- API Gateway.
