

\# ADR-008: Selección de la plataforma de orquestación



\## Estado

Aceptado.



\## Contexto



La arquitectura propuesta contempla cuatro microservicios independientes: Search, Audit, Export y Media.



También requiere ejecutar un API Gateway y un broker de mensajería NATS JetStream.



La plataforma de orquestación debe permitir administrar los contenedores, configurar redes internas, definir volúmenes persistentes y facilitar el despliegue y mantenimiento de los servicios.



La máquina virtual disponible para el proyecto cuenta con:

\- 2 vCPU.

\- 6 GB de RAM.

\- Ubuntu Server.



Se debe seleccionar una alternativa que se adapte a estos recursos y que no agregue complejidad operativa innecesaria.



\## Decisión



Se selecciona Docker Compose como herramienta de orquestación de contenedores.



Docker Compose permitirá definir y ejecutar los microservicios y sus dependencias mediante archivos declarativos YAML.



Se utilizarán:

\- Servicios independientes para cada microservicio.

\- Redes internas para la comunicación entre contenedores.

\- Volúmenes persistentes para los datos que lo requieran.

\- Variables de entorno para la configuración.

\- Políticas de reinicio y comprobaciones de salud cuando corresponda.



La configuración deberá contemplar los recursos limitados de la máquina virtual y evitar un consumo excesivo de memoria y CPU.



\## Alternativas consideradas y rechazadas



\### Docker Swarm



Proporciona administración de servicios, escalabilidad y mecanismos de distribución de contenedores.



Se descarta porque las necesidades actuales del proyecto pueden resolverse con Docker Compose y no justifican incorporar una plataforma adicional de administración.



\### Kubernetes (k3s)



Ofrece capacidades avanzadas de orquestación, escalabilidad, recuperación y administración de servicios.



Se descarta porque introduce mayor complejidad de instalación, configuración y mantenimiento para el tamaño del entorno disponible.



\## Consecuencias



\### Positivas



\- Simplifica el despliegue de los microservicios.

\- Permite administrar los servicios mediante un archivo declarativo.

\- Facilita la configuración de redes y volúmenes.

\- Reduce la complejidad operativa.

\- Es adecuado para un entorno de laboratorio en una sola VM.



\### Negativas



\- No proporciona por sí solo las capacidades avanzadas de un orquestador distribuido.

\- La escalabilidad entre múltiples nodos es limitada.

\- La alta disponibilidad requiere configuraciones adicionales.

\- La administración de recursos debe realizarse cuidadosamente.



\## Consideraciones operativas



\- Definir límites de recursos cuando corresponda.

\- Utilizar volúmenes persistentes para los datos.

\- Mantener los servicios internos sin exposición innecesaria de puertos.

\- Configurar comprobaciones de salud.

\- Mantener secretos fuera del repositorio.

\- Documentar el procedimiento de despliegue y recuperación.



\## Referencias



\- Docker Compose.

\- Docker Swarm.

\- Kubernetes (k3s).
